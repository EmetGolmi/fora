Session v12
Locked Decisions
All decisions from sessions v8–v11 remain locked. New decisions from this session are marked NEW below.
DecisionWhat was decidedStatus
NEWSection D dual-path occupation
Section D of the desktop identity builder now offers two paths: (A) AI Interpreter — user types a plain-English description, FORA proposes a civic identity with SOC codes and tags, user confirms or adjusts; (B) 22-Sector + BLS SOC — 4-column card grid of 22 civilizational sectors, click to advance to step 2 where curated role chips (above) and BLS SOC search (below, 2-column grid) appear. Both paths resolve to occupation_primary and optionally soc_code on CivicProfile. Dual occupation toggle and retired checkbox appear after selection from either path.Locked
NEW22-sector system — Hebrew letter framework
The 22 sectors of the onboarding grid are derived from the Hebrew alphabet civilizational framework. Each letter maps to a civilizational sector (e.g. Chet = Law & Boundaries, Yod = Labor & Craft, Kaph = Care & Welfare). Hebrew letters are NOT displayed in the onboarding UI — only sector names, function descriptions, and civilization layer color tags. The letter system operates as the classification engine on the backend via CivilizationSector entity. Four civilization layers: Physical survival (red), Systems & infrastructure (blue), Knowledge & culture (green), Order & governance (amber).Locked
NEWBLS SOC integration in onboarding
Path B step 2 includes a live SOC search against BLS Standard Occupational Classification 2018 (867 occupations). Results are pre-filtered by the selected sector's SOC code array. Search expands to full database if no sector match. Each result shows SOC code, full title, and US worker count. Selected SOC code stored in OccupationPath.soc_code and denormalized to CivicProfile.soc_code. Source attributed to BLS with link in the UI.Locked
NEWUnion credential moved from Section G to Section F
Union credentials are not government-issued licenses and do not belong in Section G (Professional License). Section G is exclusively for state and federally issued professional licenses. Union membership belongs in Section F (Professional Organizations & Union Membership). Union verification fields (local + member ID) in Section F appear automatically when a union-affiliated tag is selected (IBEW, UAW, SEIU, Teamsters). Section G no longer has a union path or a "no license to verify" button — users without licenses simply leave Section G blank.Locked
NEWAvatar card — four templates
The right panel of the desktop identity builder shows a live avatar card carousel instead of the old checklist. Four templates: The Franchise (sports card — navy/gilt, stats block, motto, edition number), The Tome (Magic: The Gathering — amber/parchment, type line, flavor text, rarity pip), The Field Guide (Pokémon/naturalist — deep green, Civic HP, civic moves, type tags), The Blueprint (engineering drawing — navy/cyan, grid background, spec block). Four dots below the card toggle between templates. All four cards update live as the user fills in the form. Career cards cannot use licensed IP (NFL teams, Pokémon, etc.) at launch — FORA-original designs only. Licensing deals noted as future possibility.Locked
NEWAvatar card share tiers
Three share tiers control what is visible on exported cards. Tier 1 (Public): occupation, region, credential ring type only. Tier 2 (Extended): adds age range, credential type, military branch, edition number, series. Tier 3 (Full card): everything including stats, motto, rarity indicator, founding edition. Each tier produces a visually distinct export so the tier is apparent from the image. Tier system is set per-export, not per-account.Locked
NEWPrivacy Policy — 72-hour session window
Session records (IP address, linkable identifiers) are retained for 72 hours then permanently deleted. This window exists to enable Tier 3 safety actions (imminent threats, child safety, ongoing crimes). After 72 hours, FORA cannot reconstruct identity even under legal compulsion. The 72-hour window is not extendable by law enforcement request. This is a data architecture decision, not just a policy decision — the data genuinely does not exist after the window closes.Locked
NEWPrivacy Policy — three-tier law enforcement
Tier 1: FORA does not comply (foreign govts, no legal process, political orgs, data brokers, intelligence contractors). Tier 2: FORA evaluates and notifies where legally permitted (valid US subpoenas — reviews validity, notifies user if no gag order, produces minimum data, warrant canary). Tier 3: FORA acts immediately (imminent threats to identifiable persons, child safety violations, ongoing crimes with current victims). Past crime confessions = Tier 2, not Tier 3.Locked
NEWCommunity Standards — contested ideology principle
FORA describes what organizations do. It does not decree what they are. Presents factual record without resolving contested ideological characterizations. Hamas is the worked example in the document: terrorist designations presented with attribution, non-designations equally, governing authority of Gaza noted, October 7 factual record not contested, ideological characterization subject to discourse system. The distinction between contested fact and contested ideology is explicit.Locked
NEWCommunity Standards — Editorial Board governance tier
Community Standards are NOT subject to the standard amendment process. They are a separate governance tier controlled by FORA's Editorial Board during the formative period. Changes require Board approval. Supermajority override available: 75%+ of eligible pool on a second vote overrides an Editorial Board veto of a community-ratified amendment automatically. Editorial Board composition published in Transparency Report.Locked
NEWTerms of Service — dispute resolution
Arbitration first (AAA Consumer Arbitration Rules) with class action waiver. Litigation fallback: Court of Chancery of Delaware (or Wilmington federal/state courts if Court of Chancery lacks jurisdiction). Delaware law governs. FAA governs arbitration interpretation. One-year limitations period. Four exceptions to mandatory arbitration: injunctive IP relief, small claims, DMCA, cases where arbitration is unenforceable.Locked
NEWTerms of Service — user content license
User retains ownership of contributions. FORA receives worldwide, royalty-free, irrevocable, perpetual, non-exclusive license to display and preserve. License survives account deletion for non-removed contributions. License is necessary for civic record integrity — the deliberation system cannot function as a durable civic record if contributions can be retroactively erased. The four deletion options in the Privacy Policy represent user choices within this framework.Locked
NEWTerms of Service — termination at will
FORA may terminate accounts at any time, for any reason, without notice. Hardcoded violations result in immediate permanent termination with no appeal. Non-hardcoded violations may have a 72-hour cooling-off period. Non-hardcoded terminations may be appealed to the Editorial Board within 14 days.Locked
Discourse tab system
Comments anchored to section keys. 3-round deliberation (72h each). Vote threshold: 60% of eligible pool (modal view count). Last editor right of first response in Round 2. Psych mirror before posting. Moderator veto as final circuit breaker. Gold ring on confirmed credential only.Locked v11

Open Items
In priority order. Blocking items first.
Org
Editorial Board composition — publish before Gaza / Iran go live
The Community Standards references the Editorial Board 11 times. The Board needs to exist on paper with its composition published in the first Transparency Report before any contested jurisdiction pages go live. The document is written, the structure is defined — it needs to be staffed.
Org
Legal review — all three documents before any user sees them
Privacy Policy, Community Standards, and Terms of Service are confidential drafts not reviewed by legal counsel. All three must be reviewed before publication. Key areas: Delaware corporate law, Section 230 platform liability, AAA arbitration enforceability, COPPA compliance, DMCA designated agent designation, registered agent in Delaware.
Dev
Credential verification backend — NCEES, state bar, NPI, AFL-CIO
Entry flow wireframe complete, ERD specced (CivicCredential entity), UX built. Actual connections to licensing board registries not yet built. Gold ring cannot function without this. Can launch with graceful degradation (credential submitted, verification pending) but gold ring is a core trust signal.
Dev
Address-to-representative assignment — Google Civic Information API
Entry flow collects address with full explanation (HAVA/NVRA cites). Connection to Google Civic Information API (or equivalent) to resolve address to government stack not built. User completes onboarding and representative stack is empty without this.
Dev
BLS SOC data seed — 867 occupations import
The onboarding SOC search currently uses a ~35-entry subset embedded in the HTML. Production requires importing the full BLS SOC 2018 dataset (867 occupations) into the SOCOccupation table, mapped to CivilizationSector IDs, with US worker counts from OEWS. Static dataset — seed once, update on BLS SOC revision cycle.
Design
Lebanon jurisdiction page
Cross-links to Iran, Hezbollah, and Quds Force all exist. Structurally identical to Iran — same layout, same tab system, same trajectory mechanic. Most ready next jurisdiction build. Hezbollah-Lebanon relationship is the primary civic complexity.
Design
Houthis NGE page
Referenced in tickers on Iran, Gaza, and Hamas pages. No destination page. Every tick is a broken link promise. Yemen jurisdiction page would be the companion.
Design
The Duel — structured debate wireframe
All discourse system decisions are locked. The Duel is a distinct feature: two users, a formal proposition, AI fact-checking in real time, structured argument format (opening · rebuttal · cross · closing). Lives in the discourse tab but is its own experience. The most civic-forward feature on the product roadmap. No wireframe exists yet.
Design
Mobile entry flow — Option A (one question per screen)
The 12-stage mobile flow (fora_entry_flow.html) predates the dual-path occupation system. Section D on mobile still uses the old 10-category grid. Needs to be updated with the dual-path system adapted for single-column mobile layout.
Design
Cookie policy / consent banner
Minor but required. If FORA uses any tracking, analytics, or session cookies, a cookie disclosure and consent mechanism is needed. Even a minimal one. Needs to be drafted and reviewed before any analytics are added to the platform.
